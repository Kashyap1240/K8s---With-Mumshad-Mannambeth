# 🚢 Static Pods: kubelet as an Independent Captain

## 1. What are Static Pods? 📝

- **Definition:** Pods created and managed **directly by the kubelet**, with no involvement of kube-apiserver, kube-scheduler, controllers, or etcd.
- **Standalone node scenario:** Node has only `kubelet` + container runtime (containerd). No cluster, no control plane.
- **Mechanism:** kubelet watches a **designated manifest directory**; pod definition files placed there are read and turned into pods.
- **Lifecycle (file-driven):**

| Action on manifest file | kubelet behaviour |
|---|---|
| File added | Pod created |
| File modified | Pod **recreated** with the new spec |
| File removed | Pod **deleted** |
| App/container crashes | kubelet **restarts** it (self-healing) |

- ⚠️ **Pod objects only.** ReplicaSets, Deployments, Services, etc. cannot be created this way. They depend on control plane controllers; the kubelet understands only pod-level objects.

---

## 2. Configuring the Manifest Directory ⚙️

Any directory on the host works. It is passed to kubelet in one of two ways:

**Method 1: Direct flag in `kubelet.service`**

```bash
--pod-manifest-path=/etc/kubernetes/manifests
```

**Method 2: Via kubelet config file** (used by **kubeadm** clusters)

```bash
# kubelet.service
--config=kubeconfig.yaml
```

```yaml
# kubeconfig.yaml
staticPodPath: /etc/kubernetes/manifests
```

### 🔍 Finding the path on an existing cluster

1. Check `kubelet.service` for `--pod-manifest-path`.
2. If absent, find the `--config` option → open that file → look for `staticPodPath`.

---

## 3. Viewing Static Pods 👀

| Context | Command | Why |
|---|---|---|
| Standalone node (no API server) | `docker ps` (or `crictl ps` on containerd) | `kubectl` needs kube-apiserver |
| Node in a cluster | `kubectl get pods` | API server has a mirror object |

---

## 4. Static Pods in a Cluster: Mirror Objects 🪞

- kubelet accepts pod specs from **two inputs simultaneously**:
  1. **Manifest directory** → static pods
  2. **HTTP API endpoint** → pods from kube-apiserver
- For each static pod, kubelet creates a **mirror pod** (read-only) in kube-apiserver.
- **Mirror pod constraints:**
  - ✅ View / describe
  - ❌ Cannot edit or delete via `kubectl`
  - 🗑️ Delete only by **modifying/removing the manifest file** on the node
- **Naming:** Pod name is **suffixed with the node name** (e.g. `<pod-name>-node01`).

---

## 5. Use Case: Bootstrapping the Control Plane 🏗️

Static pods don't depend on the control plane, so they can **host the control plane itself**:

1. Install `kubelet` on all master nodes.
2. Write pod manifests using the images of control plane components: `kube-apiserver`, `kube-controller-manager`, `kube-scheduler`, `etcd`.
3. Place them in the manifest directory (`/etc/kubernetes/manifests`).
4. kubelet deploys them as pods and auto-restarts on crash.

- ✅ No binary downloads, no systemd service configuration, no crash babysitting.
- This is exactly how **kubeadm** bootstraps a cluster, which is why control plane components appear as pods in the **`kube-system`** namespace.

---

## 6. Static Pods vs DaemonSets ⚔️

| Aspect | Static Pods | DaemonSets |
|---|---|---|
| Created by | **kubelet** directly | **DaemonSet controller** via kube-apiserver |
| API server involvement | None (mirror only) | Full |
| Scheduler | **Bypassed**, not scheduled by kube-scheduler | **Default scheduler + NodeAffinity** |
| Typical use | Control plane components | Node-level agents (monitoring, logging, CNI, kube-proxy) |
| Managed via | Manifest files on node | `kubectl` |

---

## 🚀 Summary Cheat Sheet

- **Static pod = kubelet-managed pod from a manifest file**, independent of the control plane.
- **Only pods** are supported; no ReplicaSet / Deployment / Service.
- **Path discovery:** `--pod-manifest-path` in `kubelet.service` → else `--config` file → `staticPodPath`.
- **Default kubeadm path:** `/etc/kubernetes/manifests`.
- **No API server:** use `docker ps` / `crictl ps`. **With API server:** read-only mirror pod, name suffixed with node name.
- **Delete/modify** = edit or remove the file on the node, not `kubectl delete`.
- **Killer use case:** kubeadm runs the control plane as static pods in `kube-system`.
- **Vs DaemonSet:** static = kubelet-created, scheduler-bypassed; DaemonSet = controller-created, scheduled via NodeAffinity.
