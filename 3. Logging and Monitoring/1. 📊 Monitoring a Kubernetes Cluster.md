# 📊 Monitoring a Kubernetes Cluster

## 1. What to Monitor? 🎯

| Level | Metrics |
|---|---|
| **Node** | Node count, node health (Ready / NotReady), CPU, memory, network, disk utilization |
| **Pod** | Pod count, per-pod CPU and memory consumption |

- Required capability: **collect → store → analyze** these metrics.
- ⚠️ Kubernetes has **no full-featured built-in monitoring solution**.

---

## 2. Monitoring Solutions Landscape 🧰

| Type | Tools |
|---|---|
| Open source | **Metrics Server**, **Prometheus**, **Elastic Stack** |
| Proprietary | **Datadog**, **Dynatrace** |
| Deprecated | **Heapster**: original K8s monitoring project; **superseded by Metrics Server** |

> Heapster still appears in many older reference architectures online; treat it as **legacy**.

---

## 3. Metrics Server 🧠

- Slimmed-down successor to Heapster.
- **One Metrics Server per cluster.**
- **Function:** scrapes metrics from every node and pod → **aggregates** → keeps them **in memory**.
- ⚠️ **In-memory only: no disk persistence → no historical data.**
  - For history / trends / alerting → use Prometheus, Elastic Stack, Datadog, Dynatrace, etc.

---

## 4. How Pod Metrics Are Generated ⚙️

```
Pod containers → cAdvisor (inside kubelet) → kubelet API → Metrics Server → kubectl top
```

- **kubelet:** agent on every node; takes instructions from kube-apiserver and runs pods.
- **cAdvisor (Container Advisor):** kubelet subcomponent that collects **performance metrics from pods/containers** and exposes them through the **kubelet API**.
- **Metrics Server** polls the kubelet API on each node.

---

## 5. Deploying Metrics Server 🏗️

**Minikube**

```bash
minikube addons enable metrics-server
```

**All other environments**

```bash
git clone https://github.com/kubernetes-sigs/metrics-server.git
kubectl create -f deploy/1.8+/
```

- Deploys **pods, services, and roles** that let Metrics Server poll node metrics.
- Newer releases ship a single manifest, so the install is typically:

```bash
kubectl apply -f https://github.com/kubernetes-sigs/metrics-server/releases/latest/download/components.yaml
```

- Allow a short interval for data collection and processing before querying.

---

## 6. Viewing Metrics 👀

```bash
# Node-level CPU / memory
kubectl top node

# Pod-level CPU / memory
kubectl top pod
```

- Example from the lecture: master node at **8% CPU ≈ 166 millicores**.
- CPU unit: **millicores (m)**. 1000m = 1 core.

---

## 🚀 Summary Cheat Sheet

- **No native full monitoring** in K8s → use add-ons.
- **Heapster = deprecated** → **Metrics Server** is the lightweight replacement.
- **Metrics Server:** 1 per cluster, **in-memory**, **no history**.
- **Pipeline:** cAdvisor (in kubelet) → kubelet API → Metrics Server.
- **Install:** `minikube addons enable metrics-server` (minikube) or deploy manifests from the metrics-server repo.
- **Query:** `kubectl top node`, `kubectl top pod`.
- **Need history/alerting?** Prometheus, Elastic Stack, Datadog, Dynatrace.
